# Урок 01. Корутины и цикл событий

## Зачем вообще asyncio

asyncio — это **конкурентность в одном потоке**. Пока одна операция ждёт
(сеть, диск, таймер), цикл событий (event loop) переключается на другую.
Параллельного выполнения Python-кода нет: в каждый момент времени работает
ровно одна корутина. Выигрыш — только на ожидании (I/O-bound задачи).

| Подход            | Когда хорош                      | Цена переключения  |
|-------------------|----------------------------------|--------------------|
| `asyncio`         | тысячи одновременных I/O-операций | очень дешёво       |
| `threading`       | блокирующие библиотеки, немного I/O | дороже, GIL       |
| `multiprocessing` | CPU-bound вычисления              | дорого, отдельные процессы |

## Ключевые понятия

- **Функция-корутина** (`async def f(): ...`) — при вызове *не выполняется*,
  а возвращает **объект корутины**.
- **Объект корутины** — «замороженное» вычисление. Запускается, только когда
  его `await`-ят или оборачивают в задачу (урок 02).
- **`await x`** — приостановить текущую корутину, пока `x` не будет готов.
  `x` должен быть *awaitable*: корутина, `Task`, `Future` или объект
  с методом `__await__`.
- **Цикл событий** — планировщик: хранит готовые к запуску колбэки,
  таймеры и I/O-события, по очереди «будит» корутины.
- **Точка переключения** — каждый `await`, который реально уходит в цикл.
  Между двумя `await` ваш код выполняется атомарно относительно других корутин.

```python
import asyncio

async def hello():
    print("start")
    await asyncio.sleep(1)    # здесь цикл может выполнять другие корутины
    print("end")
    return 42

coro = hello()                # ничего не напечатано! это объект корутины
result = asyncio.run(coro)    # создаёт цикл, выполняет корутину, закрывает цикл
```

## Точки входа

- `asyncio.run(coro, *, debug=None)` — главный способ. Создаёт **новый** цикл,
  выполняет корутину, отменяет оставшиеся задачи, закрывает async-генераторы
  и executor, закрывает цикл. Нельзя вызвать, если цикл уже запущен в этом
  потоке → `RuntimeError`.
- `asyncio.Runner` (3.11+) — то же самое, но цикл живёт между несколькими
  вызовами:

  ```python
  with asyncio.Runner() as runner:
      runner.run(init())
      runner.run(main())
      loop = runner.get_loop()
  ```
- `asyncio.get_running_loop()` — текущий цикл *изнутри* корутины/колбэка.
  Вне цикла — `RuntimeError`. Старый `get_event_loop()` в новом коде не
  используйте.

## `asyncio.sleep`

- `await asyncio.sleep(delay, result=None)` — неблокирующая пауза,
  возвращает `result`.
- `await asyncio.sleep(0)` — особый случай: «уступить» цикл, дать поработать
  другим задачам. Классический способ вставить точку переключения.
- `time.sleep()` внутри корутины **блокирует весь цикл** — ошибка №1
  новичков (подробно в уроке 09).

## Время цикла

`loop.time()` — монотонные часы цикла (как `time.monotonic()`). Именно их
используют таймеры (`call_later`, `sleep`, `timeout`). Для замеров длительности
внутри async-кода берите их.

## Протокол awaitable

Любой объект с методом `__await__`, возвращающим **итератор**, можно
`await`-ить. Корутина, `Future`, `Task` реализуют его. Свой awaitable проще
всего сделать делегированием:

```python
class Answer:
    def __await__(self):
        yield from asyncio.sleep(0.1).__await__()
        return 42

value = await Answer()   # 42
```

## Частые ошибки

1. Забыли `await` → получаете объект корутины вместо результата и
   `RuntimeWarning: coroutine '...' was never awaited`.
2. `time.sleep` / `requests.get` внутри `async def` → цикл стоит.
3. Последовательные `await` не конкурентны: `await a(); await b()` займёт
   `t(a) + t(b)`. Для конкурентности нужны задачи (урок 02).
4. Вызов `asyncio.run()` из уже работающего цикла (например, в Jupyter).
