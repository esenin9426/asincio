# Проект 1. Асинхронный веб-краулер

Объединяет уроки 03–07 и 13: таймауты, отмена, структурированная
конкурентность, семафоры, асинхронные контекстные менеджеры — плюс
HTTP-клиент aiohttp.

Проверка: `uv run pytest projects/p01_crawler -v` (БД не нужны: тесты
поднимают свой сайт на aiohttp.web).

## Что строим

Краулер обходит сайт начиная со стартовой страницы, ходит по ссылкам и
собирает статус, заголовок и ссылки каждой страницы. Он должен быть
**вежливым** к серверам (ограничение нагрузки на хост), **устойчивым**
(таймауты, повторы, ошибка одной страницы не роняет обход) и
**корректно отменяемым**.

Все параметры — в `CrawlConfig`, результат — `CrawlResult`
(`crawler.py`).

## Части

### 1. Разбор HTML — `extract_links`, `extract_title`

Синхронный код на `html.parser.HTMLParser`. Ссылки делаются абсолютными
(`urllib.parse.urljoin`), фрагменты отбрасываются (`urldefrag`), остаются
только `http`/`https`, повторы убираются с сохранением порядка.

### 2. `HostLimiter`

Словарь «хост → `Semaphore`», асинхронный контекстный менеджер
`slot(host)`. Подвох — уборка: семафор нужно удалить, когда хостом
никто не пользуется, **в том числе если ожидающую задачу отменили**.
Считайте «пользователей» хоста (владельцы + ожидающие) и удаляйте
семафор в `finally`, когда счётчик стал нулём.

### 3. `fetch` — таймаут и повторы

```
попытка 1 ──5xx/ошибка──► пауза d ──► попытка 2 ──► пауза 2d ──► попытка 3 ...
```

- таймаут — на каждую попытку отдельно (`asyncio.timeout`);
- повторяются только «временные» сбои: 5xx, `aiohttp.ClientError`,
  `TimeoutError`; 4xx — ответ сервера, повторять бессмысленно;
- экспоненциальная пауза (exponential backoff) не добивает
  перегруженный сервер. В реальных системах к ней добавляют случайный
  разброс (jitter); здесь не нужно — тесты проверяют время.

### 4. `crawl` — обход

Обход в ширину **по уровням**:

```
уровень 0: [start]                    ← TaskGroup, ждём весь уровень
уровень 1: [ссылки со start]          ← TaskGroup
уровень 2: [новые ссылки уровня 1]    ...
```

Почему по уровням, а не общей очередью с воркерами: при общей очереди
быстрая ветка может обнаружить страницу по длинному пути раньше, чем
медленная — по короткому, и «глубина» окажется неверной. Ценой
небольшого простоя на границе уровней получаем точную глубину и простой
код.

Ограничения действуют одновременно:

- общий `Semaphore(max_concurrency)`;
- `HostLimiter(per_host_limit)` на netloc URL;
- бюджет `max_pages` — уменьшается при постановке URL в уровень, поэтому
  лишние запросы не уходят вовсе.

Отмена: если все загрузки уровня запущены внутри `TaskGroup`, отмена
`crawl()` автоматически отменит их и дождётся завершения — висящих
задач не останется. С «голыми» `create_task` пришлось бы делать это
вручную.

## Подсказки по aiohttp

```python
async with aiohttp.ClientSession() as session:      # одна сессия на весь обход
    async with session.get(url) as resp:
        status = resp.status
        text = await resp.text()
```

- Сессия держит пул соединений; создавать её на каждый запрос — дорого.
- Ошибки соединения — подклассы `aiohttp.ClientError`
  (`ClientConnectorError`: не удалось подключиться).
- Ограничить соединения можно и на уровне сессии:
  `aiohttp.TCPConnector(limit=..., limit_per_host=...)`. Здесь мы делаем
  это сами, чтобы потренироваться.
