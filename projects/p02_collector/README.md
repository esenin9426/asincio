# Проект 2. Сборщик событий: TCP → очередь → ClickHouse

Объединяет уроки 04, 06, 07, 10 и 18: TCP-сервер на streams, ограниченная
очередь и backpressure, фоновый писатель с пачками и таймером, повторы,
graceful shutdown.

Подготовка: `docker compose up -d --wait`.
Проверка: `uv run pytest projects/p02_collector -v` (тесты `parse_event`
работают и без БД).

## Что строим

Сервис приёма аналитических событий. Клиенты держат TCP-соединение и шлют
по строке JSON на событие. Сервис подтверждает каждое событие и пишет их в
ClickHouse **пачками**.

```
 клиент ─┐   строки JSON    ┌──────────────┐  put (ждёт,  ┌───────┐  get   ┌──────────┐ insert ┌────────────┐
 клиент ─┼────────────────► │ обработчики  │─────────────►│ Queue │──────► │ писатель │───────►│ ClickHouse │
 клиент ─┘ ◄── OK / ERR ─── │ соединений   │ если полна)  │(maxsize)       │ (1 задача)       └────────────┘
                            └──────────────┘              └───────┘        └──────────┘
```

## Части

### 1. `parse_event` — протокол

Чистая синхронная функция: байты → кортеж для вставки или `ValueError`.
Валидация на входе дешевле, чем ошибка вставки целой пачки в БД.
Учтите, что в Python `True` — это `int` (`isinstance(True, int)`).

### 2. `Collector` — сервер

**Обработчик соединения** (`asyncio.start_server`):

- читает построчно. Ограничение длины строки задаётся параметром `limit=`
  у `start_server`: `readline`/`readuntil` при переполнении бросают
  `LimitOverrunError`/`ValueError` (урок 10);
- `OK` отправляется только **после** `await queue.put(...)`: подтверждение
  означает «событие у нас и не потеряется»;
- обрабатывает разрыв соединения клиентом (`ConnectionError`) и всегда
  закрывает writer.

**Backpressure.** Очередь ограничена. Когда БД не успевает, очередь
заполняется, обработчики ждут в `put()` и перестают читать сокет. Буфер
ядра заполняется, и клиенты притормаживают сами — память сервиса не
растёт. С неограниченной очередью медленная БД рано или поздно привела бы
к OOM.

**Писатель** — одна задача:

```
get() первого события → дедлайн = now + flush_interval
пока пачка не полна:  get() с таймаутом до дедлайна (asyncio.timeout_at)
insert(пачка) с повторами
```

Таймер считается от первого события пачки: на пустой очереди писатель
просто спит в `get()` и не просыпается впустую.

**Повторы.** Сетевые сбои ClickHouse временные: повторяем с
экспоненциальной паузой. Если и это не помогло, пачку не повторяем вечно:
очередь бы встала, а за ней и все клиенты. Считаем потери
(`stats["dropped"]`) и продолжаем. В продакшене такие пачки сохраняют на
диск (dead letter) и дозаписывают позже.

**Graceful shutdown** (`aclose`) — порядок важен:

1. `server.close()` — новых соединений нет;
2. закрыть текущие соединения: отменить задачи-обработчики и дождаться
   их (храните их в множестве; в Python 3.13 `server.wait_closed()` тоже
   ждёт закрытия соединений);
3. сообщить писателю «больше ничего не будет». Удобно положить в очередь
   объект-«стоп» (sentinel): всё, что лежит до него, гарантированно
   будет записано;
4. дождаться писателя.

Если просто отменить писателя, подтверждённые события пропадут. Тест
`test_graceful_shutdown` это проверяет.

## Как проверить руками

```bash
uv run python -c "
import asyncio, clickhouse_connect
from dbtest import CH_CONFIG
from projects.p02_collector.collector import Collector, SCHEMA

async def main():
    client = await clickhouse_connect.get_async_client(**CH_CONFIG)
    for s in SCHEMA:
        await client.command(s.replace('CREATE TABLE', 'CREATE TABLE IF NOT EXISTS'))
    c = Collector(client, flush_interval=1)
    print('port', await c.start(port=9009))
    try:
        await asyncio.Event().wait()
    finally:
        await c.aclose()
        print(c.stats)

asyncio.run(main())
"
# в другом терминале:
echo '{\"ts\": 1767268800, \"user_id\": 1, \"kind\": \"click\", \"amount\": 1}' | nc 127.0.0.1 9009
```

## Дополнительно (без тестов)

- Остановка по `SIGTERM`/`SIGINT` (урок 14: `loop.add_signal_handler`).
- Несколько писателей и ограничение параллельных вставок семафором.
- Дедупликация повторов через `insert_deduplication_token` (урок 18,
  задача 7) — чтобы повтор после «потерянного ответа» не задваивал пачку.
- Rate limit на клиента через Redis (урок 17).
- Метрики: размер очереди, задержка от приёма до записи; endpoint
  `STATS` в протоколе.
